# THE ONE 최초의 불씨

최초의 인간이 태초의 악과 단 한 번의 전쟁을 치르는 2D 도트 액션 게임의 개발 기준 문서다. 하나의 경기장, 하나의 보스, 다섯 페이즈를 끝까지 돌파하는 고난도 1인 레이드이며, 매 도전의 무기와 각인 선택으로 공략이 달라진다.

가제는 **THE ONE 최초의 불씨**. 플레이어는 처음부터 신이 아니다. 적에게서 떨어져 나온 세계의 성질을 자신의 공격으로 바꾸면서, 훗날 신이라고 불릴 존재가 된다.

**M5 표현·도감·조작 설정 구현.** 독자적인 도트 자산과 상태별 애니메이션, 원본 음악·효과음, 도감과 키보드·패드 재지정을 연결했다. 무기 5종·제단·각인 12종·무저 5페이즈와 로컬 프로필을 플레이할 수 있다. 2026년 10월 16일 기준이며 무각인·3개 시드의 무기별 자동 완주와 실제 Godot 창 실행을 검증했다. 사람의 학습 난도·음질 평가는 후속 플레이테스트가 필요하다.

## 실행

프로젝트 폴더에서 PowerShell로 실행한다. 준비된 엔진은 **Godot 4.5.2 stable**이다.

```powershell
powershell -ExecutionPolicy Bypass -File tools\run_game.ps1
```

시작 화면에서 정식 도전 또는 잔향 연습을 선택하고 J 또는 Enter를 누른다. 정식 도전은 P1부터 P5까지 이어진다. 기본 창은 1280×720이며 전투 논리 해상도는 640×360이다. 편집기를 열려면 같은 명령 뒤에 `-Editor`를 붙인다.

| 행동 | 키보드 | 게임패드 |
|---|---|---|
| 이동 | WASD / 방향키 | 왼쪽 스틱 |
| 공격 | J, 누를 때마다 1회 | X / 서쪽 얼굴 버튼 |
| 회피 | Space / K | A / 남쪽 얼굴 버튼 |
| 일시정지 | Esc | Start |
| 메뉴 선택과 확인 | 위·아래 / J·Enter | 스틱 / 서쪽 얼굴 버튼 |
| 빠른 재도전 | R | 결과 메뉴에서 선택 |
| 판정 디버그 | F1 | 키보드 사용 |

설정 → 조작 재지정에서 이동 4방향·공격·회피·일시정지의 키보드 키와 패드 공격·회피·일시정지 버튼을 바꿀 수 있다. 메뉴의 방향키·Enter·Esc는 복구용으로 유지한다. 재지정 확인 입력은 전투로 이어지지 않는다. 같은 화면에서 기본값 복원과 스틱 데드존 조절을 제공한다.

무기별 스택을 채우면 다음 공격이 비기로 바뀐다. 기운은 다음 몇 번의 공격을 바꾸며, 비기도 준비되어 있으면 공명이다. 획득 직후에는 새로 공격키를 눌러야 한다.

| 무기 | 기본 피해 | 비기 필요 스택 | 특성 |
|---|---:|---:|---|
| 잿빛 검 | 18 | 6 | 전방 베기 / 개벽 |
| 첫 가시창 | 27 | 5 | 좁고 긴 찌르기 / 일선 |
| 쌍생 송곳 | 7.5+7.5 | 8 | 5·10틱 두 타격, 행동당 스택 한 번 / 맥동 |
| 묘비 망치 | 44 | 4 | 긴 준비, 지면 충격 / 초석 |
| 척추 사슬 | 27 | 6 | 먼 거리 휘두르기, 발점 거리 36px 미만 사각 / 윤회 |

타이틀의 시작 무기 메뉴에서 발견한 무기를 고른다. 처음에는 검만 선택할 수 있다. 나머지 네 무기는 경기장 제단에 시드별로 배치된다. 제단 중심 14px 안에서 이동·공격·회피 없이 **33틱(0.55초) 대기**하면 교환한다. 스택은 초기화하고 체력·기운은 유지한다. 같은 제단을 다시 사용하려면 20px 밖으로 나가야 한다. 정식 도전에서 실제 교환한 무기는 즉시 발견 저장된다.

| 기운 | 횟수와 효과 |
|---|---|
| 화염 | 2회, 직접 피해와 2초 지속 피해 |
| 서리 | 1회, 명중 시 3초 동안 다음 피격 한 번의 피해 20% 감소 |
| 번개 | 3회, 사거리 +20px |
| 공허 | 1회, 강한 단발 피해 |

P1~P4를 끝내면 체력을 15 회복하고 1.5초 재배치와 1초 재개 예고를 거친다. **P1·P2·P3 뒤에는 각인 세 후보 중 하나를 선택하거나 건너뛴다.** 선택 중 전투 시간은 멈춘다. 최대 세 각인을 보유하며 중복·배타 후보는 제외한다. 스택과 보유 기운은 유지하고 바닥 위험과 지속 피해를 정리한다. P5 처치 시 첫 새벽의 승리 화면으로 이동한다.

잔향 연습은 정식 도전에서 도달한 페이즈만 선택할 수 있다. 연습은 선택 무기·체력 100·스택 0·기운과 각인 없음으로 시작하고 해당 페이즈만 진행한다. 제단과 기운을 사용할 수 있다. 연습 결과는 정식 기록·발견·새 해금에 반영하지 않는다.

타이틀에서 시드를 지정하고 결과·일시정지 메뉴에서 같은 시드 또는 새 시드로 재도전할 수 있다. 설정은 장식 파티클·전체 화면·판정 표시·효과 줄이기·음향·조작 재지정을 제공한다. 전체·음악·효과음 음량을 따로 조절하고 음악이나 효과음을 끌 수 있다. 소리와 장식 효과를 꺼도 필수 위험 예고는 남는다.

타이틀과 일시정지의 **불씨의 기록**은 무기·기운·각인·무저의 기억 네 분류다. 발견한 무기와 정식에서 본 패턴을 공개하며, 같은 패턴을 정식에서 두 번 이상 맞으면 대응 원리를 보여 준다. 방향키·Tab 또는 패드 LB/RB로 분류를 바꾸고 위·아래로 기록을 읽는다. 마지막 승리의 칭호와 표식은 현재 무기와 실제로 가장 많이 사용한 속성으로 정한다.

엔진 실행파일은 `.tools/godot/`에 준비되어 있다. 다른 컴퓨터로 소스만 옮긴 경우 Godot 4.5.2 Standard를 준비하고 `-GodotPath '엔진 실행파일 경로'`로 지정할 수 있다. 런처는 캐시·로그·사용자 데이터를 `.tools/runtime-data/`에 격리한다. **`user://profile.json`**에 조작·음향을 포함한 설정·발견 무기·도달 페이즈·본 패턴과 피격 경험·정식 기록 최근 100개·별도 최고 승리 기록을 저장한다. M4의 schema 1 파일은 새 설정의 기본값을 채워 이어 읽는다. 마지막 정상 파일은 `.bak`이며 손상 시 복구 안내를 표시한다. 처음 실행할 때 기존 `m3_practice.json`의 해금을 이전한다. 진행 중 전투는 저장하지 않는다. 편집기나 다른 사용자 데이터 경로에서 직접 실행하면 별도 프로필을 사용한다.

## 검증 실행

```powershell
powershell -ExecutionPolicy Bypass -File tools\test_all.ps1
```

기존 전투·저장·안전 경로에 M5 아트·음향·도감·조작 검사를 더하고, P1·5페이즈·재지정 입력·무기별 3개 시드 완주를 실행한다. 전체 완주는 시간이 걸린다. `-SkipPlaythrough`는 규칙·자산·피격 정책 검사만 실행한다. 개별 검사는 `tools\test_game.ps1 -TestScript res://tests/m5_ui_tests.gd`처럼 지정한다. 실행 전 프로젝트를 import하며 엔진 종료 코드와 스크립트 오류 로그를 모두 확인한다. 상세 로그는 `.tools/runtime-data/validation/`에 남는다. 네이티브 GPU·반전 렌더 검사는 [M5 개발 결과](docs/07_M5_STATUS.md)의 별도 명령을 따른다.

현재 구현·무기 조정 수치·실측 범위와 제한은 [M5 개발 결과](docs/07_M5_STATUS.md)를 참고한다. 그림 자산과 생성 프롬프트는 [아트 제작 기록](assets/art/README.md), 합성 음향의 소스는 [음향 제작 기록](assets/audio/README.md)에 있다.

## 반드시 유지할 게임의 중심

- 전투 스테이지 하나와 보스 개체 하나. 페이즈가 바뀌어도 같은 전쟁을 계속한다.
- 이동, 공격, 회피만으로 전투한다. 무기와 기운은 다음 공격의 성질을 바꾼다.
- 피해를 주기 위해 위험한 거리를 드나들고, 보스가 흘린 힘을 획득할 동선을 판단한다.
- 어려움은 예고를 읽고 올바르게 대응하는 데서 나온다. 무작위 즉사나 반복 노가다로 난도를 만들지 않는다.
- 사망하면 도전을 처음부터 시작한다. 도달한 페이즈는 같은 경기장의 별도 연습 모드에서 익힐 수 있다.

## 개발 시작점

현재 구현은 **Godot 4.5.2와 GDScript, Windows 싱글플레이**다. 실제 등각 좌표 변환 없이 2D 지면 좌표와 비스듬한 도트 표현을 사용한다.

M5의 표현·음향·도감·조작 재지정과 수치 조정까지 구현했다. 이후에는 사람 대상 플레이테스트로 읽기·음질·학습 난도를 평가하고, 여러 기기에서 성능과 패드 호환을 확인한다. [개발 인계서](docs/03_IMPLEMENTATION_HANDOFF.md)의 M1·M2 전달 프롬프트는 첫 구현의 기록이다. 후속 작업은 현재 코드와 M5 결과를 읽고 이어간다.

## 문서의 우선순위

게임의 범위와 플레이 규칙은 게임 설계서, 개별 보스 패턴의 수치와 선택 규칙은 보스 설계서, 동일 틱 사건 처리와 개발 수락 조건은 개발 인계서가 기준이다. 구현하면서 수치를 바꾸면 해당 원본 문서도 함께 바꾼다. 미래 확장 아이디어를 초기 필수 기능으로 확대하지 않는다.
