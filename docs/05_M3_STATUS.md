# THE ONE M3 개발 결과

이 문서는 M3 완료 당시의 기록이다. 현재 구현은 [M5 개발 결과](07_M5_STATUS.md)와 README를 따른다.

2026년 10월 16일, Godot **4.5.2.stable.official.6ce3de25a**와 GDScript로 M3의 전투 전체를 구현했다. 정식 도전은 한 경기장에서 P1~P5를 연속 진행하며 마지막 처치로 끝난다. 검 하나와 임시 도형 표현을 사용한다.

## 플레이 방법

프로젝트 폴더에서 다음 명령을 실행한다.

```powershell
powershell -ExecutionPolicy Bypass -File tools\run_game.ps1
```

타이틀에서 위·아래로 정식 도전 또는 잔향 연습을 고르고 J/Enter로 시작한다. WASD/방향키 이동, J 공격, Space/K 회피, Esc 일시정지, R 재도전, F1 디버그 표시다. 패드는 왼쪽 스틱, 서쪽 버튼 공격, 남쪽 버튼 회피, Start 일시정지로 연결했다.

## 구현 범위

| 기능 | 동작 |
|---|---|
| 정식 전투 | P1 1000, P2 1100, P3 1200, P4 1300, P5 1400의 독립 체력. 합계 6000 |
| 페이즈 전환 | 15 회복, 90틱 재배치와 60틱 재개 예고, 스택·보유 기운 보존, 이전 공격·장판·잔향·지속 피해 제거 |
| P2 | 서리의 영토, 맞물리는 고리, 얼어붙는 지평 |
| P3 | 세 번째 심장, 번개의 궤적, 멎은 심장 |
| P4 | 남은 칼날, 지워지지 않는 발자국, 갈라진 순간 |
| P5 | 최초의 처형, 마지막 지평, 이름 없는 끝 |
| 기운 | 화염·서리·번개·공허. 각 페이즈 체력 손실 임계치에 생성하고 P5는 시드별 순환 |
| 연습 | 정식 도달 페이즈만 선택, 해당 구간 완료로 종료, 체력 100·스택 0·기운 없음 |
| 해금 저장 | 정식 도달 최고 페이즈만 로컬 저장. 연습·개발용 직접 진입은 해금하지 않음 |
| 결과 분리 | 정식 승리·사망·중단 기록은 세션 동안 보관. 연습 결과는 정식 기록에 포함하지 않음 |
| 화면 | 다섯 체력 구간, 페이즈별 팔레트와 실루엣 변화, 속성별 도형, 서리 보호, 순서·잔향·재개 안내 |

P1~P4 동시 사망은 실패다. 정식 P5와 연습 완료에서 같은 틱의 동시 사망은 성공이다. M1·M2 회귀용 prototype 모드의 P1 동시 사망 실패 규칙은 유지했다.

각인 선택과 다른 무기는 M4에서 연결한다. M3의 전환은 각인 선택 없이 회복·재배치·재개를 진행한다.

## 전투 계약과 수정

- 네 속성 모두 같은 검의 준비·타격·회복·회피 취소 시점을 사용한다. 실제 공격 시작에 종류·기운·방향·사거리를 저장한다.
- 서리는 명중한 뒤 다음 유효 피격 한 번만 20% 줄인다. 같은 틱에 새로 얻은 보호막은 이미 정산된 피해를 줄이지 않는다.
- 번개는 공격 사거리만 20px 늘린다. 공허는 단발 피해 계수 2.1이며 추가 조작이나 무적을 만들지 않는다.
- 기운의 모든 착지와 만료를 먼저 처리하고, 착지 틱과 생성 ID 순서로 접촉 획득을 정산한다. 다른 속성을 보유하거나 같은 속성이 가득 찼으면 바닥 기운을 남긴다.
- 개별 타격의 ID로 중복 피해를 막는다. 연타는 별도 이벤트이고 잔향은 기록한 위치와 방향을 유지한다.
- 돌진의 실행 판정은 한 틱에 실제 이동한 구간의 swept capsule이다. 몸체가 정면의 플레이어를 피해 판정 밖으로 먼저 밀어내지 않도록 돌진 중 몸체 분리를 생략한다.
- 적법하지 않은 영역 배치는 같은 백의 다른 패턴을 먼저 확인한다. 전부 불가능하면 60틱 비공격 재배치 후 지정 대체 패턴을 사용한다. 대체까지 실패하면 안전 오류 결과로 종료하며 무한 재시도하지 않는다.
- 패턴 선택을 보류했다가 복원할 때 셔플 백에 같은 패턴을 남기지 않는다. 정상 선택에서 같은 패턴이 연속되지 않게 한다.
- 구르기 중 몸체 통과가 진행 중이면 다음 패턴 생성을 기다린다. 공격·피격으로 이동이 잠긴 상태는 남은 잠금 시간만큼 안전 경로의 이동 예산을 보수적으로 줄인다.

## 구조와 수치 원본

| 파일 | 역할 |
|---|---|
| `data/combat.json` | 플레이어·검·네 속성·페이즈별 체력과 패턴 목록·전환 수치 |
| `data/boss_patterns.json` | 전체 15패턴의 예고·잠금·실행·회복·피해와 기하 수치 |
| `scripts/boss_patterns.gd` | 패턴 타임라인, 영역 배치와 연속 안전 경로, 돌진과 위치 기록 |
| `scripts/combat_geometry.gd` | 판정과 화면에 공유하는 부채꼴·선·파동·원판·바깥 고리·통로·캡슐 |
| `scripts/combat_model.gd` | 모드, 페이즈, 플레이어·자원·피해·기운·감독·전환·종료 |
| `scripts/main.gd` | 입력, 화면과 메뉴, 해금과 세션 기록, 실제 시간의 정지 |
| `scripts/practice_profile.gd` | 버전과 해금 ID 검사, 임시 파일 후 교체로 연습 해금 저장 |

전투 모델의 `reset(seed)`는 기존 회귀 검증을 위해 prototype을 유지한다. 실제 타이틀은 `reset(seed, "official", 1)`을 사용한다. 연습은 `reset(seed, "practice", phase)`다. 모델의 시작 페이즈 인자는 개발·검증에서도 쓰지만 일반 정식 메뉴는 항상 P1에서 시작한다.

## 검증

검증 스크립트와 실행 명령은 README에 있다. 정상 입력 완주는 실제 모델에 이동·공격·회피만 전달하며 체력, 피해, 위치, 전투 자원, 페이즈를 조작하지 않는다.

최종 자동 검사 합계는 **1,317개, 실패 0개**다. 기존 전투 103개, M3 규칙 319개, 장면 통합 55개, 안전 경로 840개로 구성된다. 정상 입력 완주 실행은 이 검사 수와 별도로 수행했다.

| 검증 | 확인한 내용 |
|---|---|
| 기존 전투 회귀 | 이동·회피·공격·스택·화염·기운·prototype 종료의 기존 규칙 |
| M3 규칙 | 4회 전환, 독립 체력과 초과 피해 차단, 네 속성, 연습·정식 종료, 프로필 복구, 패턴 타이밍과 이벤트 ID |
| 장면 통합 | 메뉴 잠금과 해금, 입력·일시정지·히트스톱, 전환 후 새 누름, 기록 분리와 재도전, 안전 오류 결과의 기록 제외 |
| 안전 경로 | 23개 합법 시작 상태와 197개 경로, 실제 판정 72,745틱, 배치 실패 시 대체 6건 |
| 회피 거리 | 마지막 지평에서 64.8·72·74.52·82.8px 각각의 전 구간을 재생, 무적 3~14틱만 인정 |
| P1 완주 | 기존 5개 시드의 정상 입력 회귀 |
| 전체 완주 | 3개 시드에서 기본 체력 100과 보스 합계 6000으로 P1~P5 연속 승리, 전체 15패턴 관측 |
| 실제 실행 | Godot OpenGL 창에서 타이틀·연습 잠금·P2 고리·P4 잔향·P5 화면을 캡처해 확인 |

첫 전체 완주 결과는 약 11분 36초~11분 50초의 전투 틱 시간이다. 렌더링, 히트스톱과 사람의 판단 지연은 이 순수 모델 시간에 포함하지 않는다. 자동 정책의 완주는 피할 수 있는 입력 경로를 확인하며, 사람의 첫 도전 난도나 재미를 보장하지 않는다.

최종 코드에서 재확인한 정식 완주 결과는 다음과 같다. 모든 실행에서 15패턴과 전체 6000 피해, P1→P2→P3→P4→P5의 순서를 확인했다. 체력 보정이나 테스트 피해 주입을 사용하지 않았다.

| 시드 | 결과 | 전투 틱 | 종료 체력 |
|---|---|---:|---:|
| 1 | 정식 승리 | 41,896 | 100 |
| 2 | 정식 승리 | 42,606 | 100 |
| 7 | 정식 승리 | 41,775 | 100 |

시드 2에서는 P3 연타에 한 번 피격됐고 후속 페이즈의 정상 회복으로 체력이 복구됐다. 화염·서리·번개·공허 사용과 공명 사용도 실행 전체에서 확인했다.

## 저장 범위와 남은 확인

연습 해금은 `user://m3_practice.json`에 schema 1과 최고 도달 페이즈만 저장한다. 제공된 런처는 이 사용자 데이터를 프로젝트의 `.tools/runtime-data/` 아래로 격리한다. 같은 실행 방법을 유지하면 다음 실행에서 해금을 읽는다. 엔진을 다른 사용자 데이터 경로로 직접 실행하면 별도 저장 파일을 사용한다.

진행 중 전투, 전체 설정과 공식 최고 기록의 영구 저장은 M4 범위다. 최종 도트 아트·오디오·키 재지정도 아직 구현하지 않았다. 실제 물리 키보드·패드로 사람이 전투 전체를 완주하는 확인, 여러 GPU에서의 성능 측정, 사람이 체감하는 난도 조정은 남아 있다.

개발용 `--practice=N` 또는 `--phase=N`은 잠금과 무관하게 지정 페이즈의 연습 화면을 검증하는 인자다. 화면에 DEV PRACTICE로 표시하고 정식 기록이나 해금에 반영하지 않는다. 일반 메뉴의 잠금 규칙과 구분한다.

## M4 인계

1. 나머지 네 무기와 제단의 의도적인 교환을 현재 공격 스냅샷·기운 계약에 연결한다.
2. P1~P3 종료 후 각인 후보와 선택을 전환 사이에 넣는다.
3. 발견 무기, 설정, 공식 기록을 포함하는 프로필로 연습 해금 저장을 이전한다.
4. 실제 무기별 공격 기회와 기운 수집 경로, 각인 배타·임계치 변경을 검증한다.
5. 기존 15패턴의 읽기와 판정을 유지하며 빌드별 안전 경로와 전투 시간을 다시 측정한다.
