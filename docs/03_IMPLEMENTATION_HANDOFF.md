# THE ONE 개발 인계서

## 개발 목표와 결정의 성격

이 프로젝트는 하나의 경기장에서 다섯 페이즈의 보스 무저를 상대하는 2D 도트 액션 게임이다. 구현자는 [게임 설계서](01_GAME_DESIGN.md)와 [보스 설계서](02_BOSS_DESIGN.md)의 전투 문법을 보존하면서 작은 플레이 가능한 단위로 완성한다.

이 문서는 2026년 10월 16일 작성한 전체 개발 계약이다. 현재 M5 기능을 구현했으며 범위와 검증 결과는 [M5 개발 결과](07_M5_STATUS.md)와 README를 따른다. 이전 결과 문서는 각 단계 당시의 기록이다. 사람의 물리 기기 완주·음질·학습 난도 평가는 아직 별도로 필요하다.

| 구분 | 항목 |
|---|---|
| 유지할 결정 | 1경기장, 1보스, 5페이즈, 이동·공격·회피, 다음 공격 치환, 도전별 빌드 초기화, 후반 연습 |
| 구현 기본안 | Godot 4 계열 안정판, GDScript, Windows 로컬 싱글플레이, 60Hz 물리 |
| 수치 조정 가능 | 피해, 체력, 사거리, 예고와 회복 시간, 이동 속도, 각인 수치 |
| 먼저 검증할 가설 | 8~12분 도전, 두 액션 버튼의 충분한 깊이, 자동 기운 획득과 의도적인 무기 교체 |
| 초기 범위 밖 | 네트워크, 계정, 서버, 상점, 제작, 다중 맵, 일반 적, 추가 직업 |

Godot는 전용 2D 작업 흐름과 사용자 정의 Resource를 제공하므로, 이 게임의 지면 판정과 데이터 중심 전투 정의에 잘 맞는다는 판단으로 선택했다. 버전은 개발 시작 시 사용 가능한 안정판 하나를 기록해 고정한다. [Godot 공식 기능 소개](https://godotengine.org/features/)

## 구현 순서와 완료 조건

단계를 건너뛰어 최종 아트와 전체 콘텐츠를 한꺼번에 만들지 않는다. 각 단계는 실행 가능한 빌드와 짧은 검증 기록으로 끝낸다.

| 단계 | 구현 범위 | 다음 단계로 넘어갈 조건 |
|---|---|---|
| M1 조작 실험 | 도형 경기장, 이동, 검 기본 공격, 회피, 보스 발톱 한 패턴, 디버그 판정 표시 | 예고와 판정 일치, 대각 속도 일정, 공격 취소와 회피 무적을 프레임 단위로 확인 |
| M2 첫 페이즈 | P1 세 패턴, 검 비기, 화염 기운, 체력, 사망과 빠른 재도전, 최소 HUD | 기운 획득이 자동 스킬을 만들지 않음, 한 페이즈를 정상적으로 승리·실패·재시작 가능 |
| M3 전투 전체 | 회색 도형으로 P2~P5와 전환, 최종 승리, 연습 모드, 모든 기운 | 5페이즈를 연속 완주, 한 번에 한 구간만 전환, 잔류 공격·동시 사건·연습 기록 분리 검증 |
| M4 도전의 변화 | 나머지 무기, 제단, 각인 12종, 시드, 무기 발견, 로컬 저장 | 무기마다 공격 기회가 달라짐, 선택 효과·배타 조건·보유 자원 이전 검증 |
| M5 표현과 완성 | 도트, 음향, 애니메이션, 옵션, 도감, 난도 조정 | 효과를 켠 상태에서도 예고를 읽음, 키보드·패드 완주, 저장·재실행·성능 확인 |

M2의 첫 전달물에는 프로젝트 실행 방법, 실제 확인한 조작, 알려진 문제, 다음 단계의 변경 범위를 적는다. 임시 그래픽이라는 이유로 판정 버그를 다음 단계로 넘기지 않는다.

## 화면과 좌표

- 월드는 2D 직교 X/Y 좌표다. 별도의 3D 월드나 수학적인 등각 투영을 도입하지 않는다.
- `ground_position`이 이동, 충돌, 사거리, Y 정렬, 지면 예고의 원본이다. 스프라이트는 이 발점에 시각적 오프셋을 더해 그린다.
- 논리 전투 화면은 640×360, 경기장은 중심 (320,184), 반경 (260,126)의 타원. 플레이어 반경 6px를 고려해 경계를 제한한다.
- 타원의 경계 처리에서 X/Y를 독립적으로 잘라 사각형처럼 만들지 않는다. 경계 법선 방향으로 밀어내고 접선 방향 이동은 유지한다.
- 물리 좌표는 실수로 유지하고 화면 출력만 픽셀에 정렬한다. 이동 좌표 자체를 매 틱 정수로 버리지 않는다.
- 고정 카메라를 사용한다. 해상도나 화면비를 바꿔도 보이는 전장과 공격 판정이 달라지지 않는다.
- 조준의 각도와 거리 계산은 지면 좌표에서 수행한다. 발점과 스프라이트 중심을 섞지 않는다.
- 그림자, 장식, 파편에는 전투 콜라이더를 붙이지 않는다. 피격 원은 보스 22px, 몸체 반경은 18px다.
- 사슬은 일반 모양 교차 검사에 더해 표적 발점 거리 36px 이상 조건을 갖는다. 큰 피격 원이 안쪽 사각을 무효화하지 않게 한다.

다음 이름은 구현용 제안이며 실제 생성된 파일이 아니다. 역할은 분리하되 각 수치마다 작은 매니저를 만드는 식으로 과도하게 쪼개지 않는다.

## 데이터 계약

Godot 사용자 정의 Resource를 기본으로 사용한다. .tres와 스크립트 클래스는 구현자가 작성한다. 최종 수치의 원본은 해당 Resource이며, 의미가 바뀌는 수치 수정은 문서에도 반영한다.

M1~M5의 실제 구현은 읽기 쉬운 JSON 정의를 사용한다. 현재 수치 원본은 `data/combat.json`, `data/boss_patterns.json`, `data/weapons.json`, `data/oaths.json`이며 아래 계약의 필드를 보존한다. 향후 Resource로 옮길 때 JSON과 두 원본을 동시에 유지하지 않는다.

| 데이터 | 필수 필드 |
|---|---|
| WeaponDefinition | id, display_name, damage_events, startup_ticks, active_ticks, recovery_ticks, dodge_cancel_tick, reach_px, arc_or_width, minimum_target_distance, stack_threshold, signature_profile |
| ElementDefinition | id, max_charges, direct_multiplier, range_bonus, on_hit_effect, ground_lifetime_ticks, icon_shape |
| OathDefinition | id, modifiers, exclusions, display_benefit, display_cost |
| BossPhaseDefinition | id, hp, opening_pattern, pattern_bag, drop_element_rule, drop_thresholds, transition_reward |
| BossPatternDefinition | id, telegraph_events, tracking_lock_ticks, damage_events, movement_events, recover_start, recover_ticks, validity_rules, fallback_id |
| DamageEvent | event_id, start_tick, end_tick, shape, source_anchor, damage, hit_limit_per_target, target_mask |
| TelegraphEvent | event_id, matching_damage_event_id, start_tick, shape_source, progress_style, sound_id |
| AttackSnapshot | action_id, kind, weapon_id, element_id, facing, origin_rule, damage_parameters, target_distance_rule, consumed_resources |
| RunState | run_id, seed, mode, phase_id, current_hp, player_loadout, oaths, random_stream_states, result |
| Profile | schema_version, settings, discovered_weapons, unlocked_practice_phases, seen_patterns, official_records |

기하 데이터를 예고용과 피해용으로 따로 수기 작성하지 않는다. 같은 형태를 공유하고 위험 시작 시간만 분리한다. 잔향의 `source_anchor`는 기록한 위치와 방향이며 현재 보스 Transform을 참조하지 않는다.

무기 직접 피해는 이벤트로 나눈다. 쌍단검은 7 피해 두 이벤트이고, 비기의 2.2배도 각각에 한 번만 적용한다. 공격의 전체 피해를 두 타격 각각에 다시 배정하지 않는다.

## 플레이어 상태 전이

| 현재 상태 | 허용 입력과 다음 상태 | 중요한 제약 |
|---|---|---|
| Idle / Move | 이동, Attack, Dodge | 같은 틱에 공격과 회피면 회피 우선, 공격 입력 폐기 |
| Attack | 취소 가능 틱 이후 Dodge, 종료 뒤 Idle / Move / 다음 Attack | 다음 공격은 최대 6틱 버퍼. 초기 준비와 타격 구간 회피 취소 불가 |
| Dodge | 종료 뒤 Idle / Move / Attack | 다른 회피로 취소 불가. 마지막 6틱에는 다음 행동 예약 가능 |
| Hurt | 12틱 뒤 Idle / Move 또는 적법한 예약 행동 | 경직 중 행동 시작 불가, 마지막 6틱 버퍼 허용 |
| Transition / Selection | 전투 행동 없음, 선택 UI만 | 남은 입력 버퍼 제거, 재개 시 버튼 재입력 |
| Dead / Victory | 결과 UI | 전투 업데이트와 신규 입력 접수 종료 |

회피 쿨다운은 시작 틱으로부터 42틱이다. 쿨다운이 6틱보다 많이 남아 있으면 회피 입력은 예약하지 않는다. 예약된 회피가 6틱 안에 시작할 수 없으면 만료하며, 훨씬 나중에 자동으로 굴러서는 안 된다.

예약 공간은 하나다. 회피가 공격보다 우선한다. 같은 종류를 다시 누르면 가장 최근 입력으로 갱신하되, 이미 예약한 회피를 나중의 공격으로 덮지 않는다. 버퍼는 매 틱 유효성을 검사한다.

### 다음 공격 변경과 입력 버퍼

공격 버튼의 새로운 누름마다 번호와 틱을 기록한다. 공격 종류를 고르는 함수는 UI와 전투가 함께 사용한다.

1. 기본/비기/속성/공명과 속성 종류를 포함하는 `next_attack_key`를 만든다.
2. 스택 완성, 기운 획득·소진, 무기 교체가 이 키를 바꾸면 아직 시작하지 않은 공격 예약을 제거한다.
3. 공격 예약의 종류는 실행 전에 다시 비교한다. 다르면 새 입력을 기다린다.
4. 이미 실행 중인 공격은 시작 스냅샷을 유지한다.
5. 같은 속성의 횟수만 보충되어 종류가 같으면 기존 예약을 지울 필요가 없다. 버튼 홀드 자체는 추가 입력을 만들지 않는다.

기운 획득과 공격 누름이 같은 틱이면 **획득 처리를 우선하고 그 틱의 공격도 예약에서 지운다**. 다음 누름을 요구한다. 이 짧은 입력 손실은 획득 피드백으로 알리고, 첫 테스트에서 조작감을 확인한다. 필요하면 추후 입력 순서 타임스탬프를 더 정밀하게 처리하되 자동 특수 소모 금지는 유지한다.

## 한 전투 틱의 사건 순서

이 순서는 같은 상황에서 결과가 달라지는 오류를 막기 위한 계약이다. 실제 Godot 콜백 호출 순서에 맡기지 않는다.

1. 정지 여부를 확인하고 전투 틱을 진행한다. 입력의 누름·해제, 현재 이동 벡터를 수집한다. 진행 중 상태의 나이와 만료를 갱신한다. 단, 화염의 만료 틱에 예정된 마지막 피해는 제거 전에 정산하도록 피해 큐에 남긴다.
2. 적법한 새 회피 또는 예약 회피를 우선 시작한다. 회피 시작의 나이는 0이며, 해당 틱에는 아직 무적이 아니다.
3. 플레이어·보스·돌진·기운 비행의 위치를 갱신한다. 경기장 경계를 처리하고 회피 중 보스 몸체 통과 규칙을 적용한다.
4. 착지한 기운 접촉과 제단 교체를 처리한다. 자원 변화가 공격 종류를 바꾸면 오래된 공격 예약을 제거한다.
5. 행동 상태가 허용하면 공격을 시작한다. 종류·방향·무기·피해 계수·자원을 고정하고 즉시 소비한다. 이번 틱에 회피를 시작했다면 공격은 시작하지 않는다.
6. 공격과 장판의 활성 이벤트를 생성하고 교차를 수집한다. 각 판정은 이 시점의 무적과 피격 기록을 기준으로 유효성을 판단한다.
7. 양측의 피해를 배치로 적용한다. 같은 틱에 플레이어에게 여러 피해가 유효하면 **감소 효과 적용 전 가장 큰 피해 하나만** 적용하고 나머지는 피해 후 무적으로 거절한다. 동률은 고정 이벤트 ID 순서로 정한다.
8. 보스의 유효한 기본 공격 피격에서 스택을 적립하고, 속성 명중 효과를 적용한다. 새 서리 보호막은 같은 틱에 이미 정산한 피해를 소급 감소시키지 않는다. 공격 종류가 달라지면 공격 버퍼를 다시 정리한다.
9. 아래의 모드별 종료 우선순위를 적용한다. 종료나 전환은 도전·구간별로 한 번만 실행한다.
10. 계속 싸우는 경우에만 회복 상태 진입, 예약 기운 방출, 다음 패턴 선택을 처리한다. 마지막으로 UI와 오디오에 결과 이벤트를 보낸다.

| 모드 | 종료 판정 우선순위 |
|---|---|
| official 정식 | P5 체력 0이면 승리, 아니면 플레이어 체력 0이면 사망, 아니면 구간 체력 0이면 다음 페이즈 전환 |
| practice 연습 | 선택한 구간 체력 0이면 practice_complete, 아니면 플레이어 체력 0이면 연습 실패 |
| prototype 시제품 | 플레이어 체력 0이면 실패, 아니면 구현된 P1 체력 0이면 prototype_complete |

정식 P5와 연습 완료는 같은 틱 동시 사망도 성공이다. 정식 P1~P4와 시제품에서 동시 사망은 실패다. 연습은 정식 승리, 새 페이즈 해금, 최초 처치에 반영하지 않는다.

M1·M2는 `prototype` 모드다. P1 완료 시 “시제품 1페이즈 완료” 결과 화면으로 돌아가며 존재하지 않는 P2로 진입하지 않는다. 정식 기록과 해금을 생성하지 않는다. M3에서 official과 practice 흐름을 연결한다.

### 무적과 지속 판정

회피 나이 3~14틱은 피해를 받지 않는다. 피해가 실제 적용된 틱부터 이후 41틱까지 피해 후 무적을 적용한다. 피해 후 무적 중 접촉한 이벤트를 이미 적중한 것으로 기록하지 않는다. 오래 남는 장판 안에 계속 있으면 무적 종료 후 그 장판의 첫 피해를 받을 수 있다.

한 이벤트에 이미 피해를 받은 대상은 그 이벤트로 다시 피해를 받지 않는다. 전투 전체를 하나의 ID로 묶어 이후 연타까지 무시하거나, 매 프레임 새 ID를 만들어 장판이 반복 피해를 주는 두 오류를 모두 막는다.

## 피해와 자원 계산

보스의 초기 방어력은 0이다. 고정 수치 차감 방어를 넣어 쌍단검을 특별히 불리하게 만들지 않는다.

```text
기본 직접 피해 = 무기의 해당 타격 피해
비기 직접 피해 = 기본 직접 피해 × 2.2
속성 직접 피해 = 기본 직접 피해 × 속성 계수
공명 직접 피해 = 기본 직접 피해 × 2.2 × 속성 계수
최종 직접 피해 = 위 결과 × 해당 공격에 적용되는 각인 계수들
```

공명의 곱셈은 두 자원을 함께 쓰는 드문 강한 한 번을 의도한 결정이다. 자원은 시작 시 소비하므로 헛공격과 취소가 비용을 갖는다. 첫 플레이테스트에서 구간을 지나치게 빨리 소모하면 공명 계수를 줄이되, 입력 규칙은 유지한다.

내부 체력과 피해는 1/1000 단위 정수로 저장하는 방식을 권장한다. 타격별 계산 결과를 마지막에 1/1000로 반올림하고, HUD의 남은 체력은 올림하여 양수인데 0으로 보이지 않게 한다. 쌍단검의 두 타격을 정수 체력으로 각각 반올림해 일관성이 깨지지 않게 한다.

O03·O04의 거리 조건은 실제 명중 순간의 양측 발점 거리로 판정한다. 공격 종류와 기본 계수는 시작 스냅샷을 따르지만, 명중 거리 조건은 명중 때 읽는다. 거리가 정확히 40px면 가까운 조건이다.

화염은 대상에 한 인스턴스만 유지한다. 부여 후 +30·+60·+90·+120틱에 피해 3씩, 최초 지속 120틱으로 총 12 피해다. **+120틱의 마지막 예정 피해를 정산한 뒤 만료**한다. 재부여 시 만료를 현재 틱 +120으로 갱신하고 다음 틱 피해 시점은 뒤로 미루지 않는다. 같은 틱에 재부여되면 갱신된 만료를 사용하므로 정산 후 제거하지 않는다. 시전 행동 하나의 여러 타격으로 반복 갱신하지 않는다. 페이즈 전환 시에는 남은 피해 없이 제거한다.

서리 보호막은 실제 명중 시 생성하고 180틱 유지한다. 다음 유효 피격 하나의 피해에 0.8을 곱한 뒤 소모한다. 회피나 피해 후 무적으로 거절된 판정에는 소모하지 않는다. 재부여는 만료를 갱신하고 중첩하지 않는다. O12 보정과는 곱연산한다.

스택 적립은 유효한 기본 공격 행동당 최대 하나다. 기본 공격의 나머지 타격이 다음 틱에 맞아도 같은 행동 ID면 추가하지 않는다. 보스의 현재 구간에 실제로 양수 피해가 들어간 경우만 적립한다.

### 각인 적용 시점

- 선택은 전투가 멈춘 상태에서 이루어지므로 실행 중 공격은 없다.
- 최대 체력이 줄면 현재 체력은 새 최대치까지 제한한다. O07은 최대 체력과 현재 체력에 각각 20을 더한 뒤 상한을 적용한다.
- O08을 선택해도 이미 들고 있는 기운 횟수를 즉시 더하지 않는다. 이후 획득·보충의 최대 횟수만 +1이다.
- 스택 임계치를 바꾼 뒤 현재 개수를 새 상한으로 제한하고 준비 여부를 다시 계산한다. O10으로 임계치가 낮아져 현재 스택 이상이면 비기를 준비시킨다. O02로 임계치가 높아지면 쌓인 개수는 유지하고 새 임계치에 도달할 때까지 준비 상태를 해제한다.
- O11의 회복 보너스는 이후 페이즈 종료부터 적용한다. 이번 전환에서 이미 받은 회복을 다시 주지 않는다.
- 각인 선택 이후 버퍼와 재입력 상태를 정리하므로 선택 확인 입력이 전투 공격으로 이어지지 않는다.

## 기운과 무기 제단 처리

기운의 생애는 `Queued → Flying → Grounded → Consumed / Expired`다. 임시 기운은 비행 24틱 후 착지시키며 Grounded가 되는 순간부터 600틱 수명을 센다. O09가 있으면 수명은 960틱이다. 획득 가능 여부는 현재 보유 종류와 횟수로 판정한다.

한 페이즈의 방출 임계치는 소모 체력 비율 0.20, 0.45, 0.70이다. 큰 피해가 여러 임계치를 넘으면 순서대로 큐에 넣고, 각 임계치 ID는 한 번만 큐에 넣는다. 각 회복 상태 진입 때 최대 하나를 방출한다. 전환 시 큐·비행·바닥 기운을 모두 제거한다.

동시에 여러 기운과 접촉하면 착지 틱이 빠른 것, 그 다음 생성 ID가 작은 것부터 검사한다. 처음 획득한 종류가 그 틱의 보유 속성이 되므로 다른 종류는 남는다. 한 번 소모된 기운은 같은 틱에 다른 처리에서 다시 획득할 수 없다.

제단 교체는 대기 상태에서만 누적한다. 해당 틱에 이동·공격·회피 입력 또는 피격이 있으면 누적을 취소한다. 피격 판정이 제단 처리 뒤에 일어나므로 **교체 완료는 틱 종료 시 확정**하고, 그 틱에 피격되면 교체도 취소한다. 교체 확정 전 공격을 시작했다면 역시 취소한다.

교체는 현재 무기와 제단 무기를 하나의 원자적 교환으로 처리한다. 양쪽 스택은 0, 기운과 체력은 유지한다. 현재 무기가 제단에도 복제되거나 제단을 비우고 다시 생성하는 틈이 생기면 안 된다. 같은 제단은 20px 밖으로 나가기 전 재활성화하지 않는다.

## 패턴의 안전 검증

첫 구현부터 범용 AI 길찾기로 모든 조합을 해결하려고 하지 않는다. 장판과 돌진에는 손으로 만든 소수의 배치 템플릿을 두고, 회전·반전·허용 위치 선택으로 변화시킨다. 모든 템플릿은 같은 예고와 피해 기하를 사용한다.

런타임에서는 플레이어 위치, 경기장 경계, 최소 속도, 가능한 회피 거리를 사용해 후보의 안전 경로를 검사한다. 초기에는 보수적으로 후보를 줄여도 된다. 피할 수 없는 배치를 허용하면서 난도라고 부르면 안 된다.

특히 P5 마지막 지평은 다음을 만족하는 검증 경로를 템플릿에 함께 둔다.

1. 현재 발점에서 예고 종료 전에 장판 밖 대기점까지 이동 가능.
2. 파동 도달 전에 대기점에서 회피 시작 가능.
3. 실제 회피 거리로 이동했을 때 시작·이동·종료 경로가 장판과 경기장 밖으로 침범하지 않음. 보스 몸체와 겹칠 때의 종료 분리까지 포함함.
4. 파동과 겹치는 시간 전체가 회피 무적 구간 안에 있음.
5. 종료 뒤 플레이어가 발점 기준 폭 32px 이상의 열린 경로를 유지함.

템플릿 검증은 가능한 고정 회피 거리 64.8·72·74.52·82.8px 각각에 대해 수행한다. 최소 거리의 종료점이 안전해도 긴 회피의 종료점은 장판에 닿을 수 있다. 각 거리마다 별도의 안전 경로를 허용한다. 런타임에서는 현재 빌드의 실제 거리를 쓴다.

회피 종료 몸체 분리는 먼저 진행 방향의 가장 가까운 발점 간 24.5px 지점을 선택한다. 외곽에 막히면 보스 설계서의 고정 각도 순서로 후보를 찾는다. 분리로 예고 영역을 가로지르는 경로와 최종 발점도 위험 검사의 일부이며, 분리 자체에 무적을 주지 않는다.

검증에 실패하면 보스 설계서의 축소·대체 규칙을 따른다. 최종 대체까지 실패하면 안전 오류 상태로 종료하고 무한 재귀나 무한 대기를 하지 않는다. 개발 중에는 사용한 템플릿, 실패 이유, 검증 경로를 오버레이로 볼 수 있어야 한다. 출발 위치를 여러 지점으로 바꾼 반복 실행에서 템플릿을 검증한다.

## 시간과 히트스톱

이동, 회피, 버퍼, 무적, 보스 예고, 장판, 스택 효과, 기운 수명은 같은 전투 틱을 사용한다. 일시정지·각인 선택·히트스톱에서 모두 멈춘다. UI 선택·메뉴 애니메이션·결과 화면은 별도 시간으로 갱신한다.

히트스톱 시작값은 기본 공격 2렌더 프레임 상당, 비기·공명 4렌더 프레임 상당의 **실시간 33ms / 67ms**다. 렌더 프레임 수를 직접 세지 않는다. 동시에 여러 타격이 생기면 합산하지 않고 큰 값 하나만 사용한다. 시작 후 최소 100ms 동안 새 히트스톱을 무시해 쌍단검이 시간을 과도하게 늘리지 않게 한다.

전투 시간 통계는 히트스톱을 제외한 틱 시간과 실제 벽시계 플레이 시간을 모두 남긴다. 8~12분 플레이 목표는 메뉴·선택을 제외하고 히트스톱을 포함한 실제 플레이 시간으로 확인한다. 보스 설계서의 DPS 계산은 틱 시간 기준의 근사치다.

히트스톱 도중에도 같은 회피 우선 버퍼 규칙을 적용한다. 회피는 공격을 덮지만 공격은 회피를 덮지 못하며, 같은 종류끼리는 가장 최근 입력 하나만 보관한다. 재개 때 자원 변경과 유효성을 다시 확인한다. 입력 누름을 유실하거나 여러 행동을 한꺼번에 실행하지 않는다.

## 시드와 저장

시드 스트림은 최소 `layout`, `boss`, `oath`, `element`, `cosmetic`으로 분리한다. 원본 시드와 스트림 상태를 로컬 개발 로그에 남긴다. 장식용 난수 호출 수가 바뀌어도 보스 공격과 보상이 바뀌면 안 된다.

같은 시드 재도전은 시작 무기와 선택한 각인이 같아야 비슷한 조건을 제공한다. 플레이어의 위치가 패턴 적법성에 영향을 주므로 **시드만 같다고 전체 전투가 같아지는 것은 아니다**. 입력 재생과 완전 결정론 리플레이는 초기 필수 기능이 아니다.

초기 저장 대상은 설정, 발견한 무기, 도달 페이즈, 본 패턴, 정식 최고 기록이다. 임시 파일 저장 후 교체하는 원자적 저장과 마지막 정상 파일 백업을 사용한다. 스키마 버전을 기록한다. 알 수 없는 ID나 깨진 파일은 안전한 기본값으로 복구하고 사용자에게 짧게 알린다.

**진행 중인 도전은 저장하지 않는다.** 일시정지는 가능하고, 종료를 선택하면 현재 도전이 끝난다는 내용을 메뉴에서 표시한다. 도전 중단을 로컬 프로필 손실과 혼동하지 않는다. 추후 이어하기를 넣을 경우 자원·페이즈·난수·바닥 오브젝트를 모두 저장하는 별도 설계가 필요하다.

발견과 도달 해금은 발생 직후 저장한다. 연습에서 발생한 결과로 프로필의 도달 페이즈나 발견 무기를 늘리지 않는다. 정식 기록은 승리·사망·중단을 구분한다. 온라인 랭킹, 클라우드 저장, 외부 분석 전송은 초기 범위에 없다.

| 오디오 | 무기별 적중, 회피·피격, 패턴 예고와 실행, 속성 획득, 단계별 음악 레이어 |

보스 다섯 페이즈를 별도의 전신 애니메이션 다섯 세트로 만들지 않는다. 원본 몸체와 공격 모션을 재사용하고 연계·잔향·부위 변화로 차이를 만든다. 플레이어도 무기마다 전신 애니메이션을 전부 복제하지 않는다.

8방향을 반전할 때 손, 무기 소켓, 궤적, 조준 방향이 일치하는지 확인한다. 시각상의 큰 팔과 실제 지면 판정의 관계를 오버레이로 비교한다. 최종 제작 전 방향당 원본 동작 수와 프레임 수를 산정하고, 거대한 스프라이트 수를 자동 생성으로 해결할 것이라고 가정하지 않는다.

### 수동 플레이 검증

- 키보드와 패드 각각으로 정식 5페이즈를 완주하고, 전투 중 추가 조작키가 필요하지 않았는지 확인한다.
- 소리 없이, 음악만 끄고, 화면 효과를 줄인 상태에서 각각 예고를 읽는다.
- 첫 진입자는 다음 공격 아이콘을 보고 기본/비기/속성/공명을 구분할 수 있어야 한다.
- 사망 화면의 원인과 실제 맞은 공격이 일치하는지 녹화로 대조한다.
- 기운을 한 번도 획득하지 않는 경로로도 전체 패턴을 회피하고 보스를 처치할 수 있어야 한다.
- 시작 무기별로 안전 공격 기회, 기운 수집률, 평균 소요 시간을 비교한다. 단순 허수아비 DPS만으로 균형을 결정하지 않는다.

### 성능과 기록

지속 60fps를 목표로 하되 특정 하드웨어 보장을 문서만으로 약속하지 않는다. 테스트한 CPU·GPU·해상도·빌드 버전과 평균 및 느린 프레임 시간을 함께 기록한다. 30·60·120fps 렌더 조건에서도 60Hz 전투 규칙이 같아야 한다.

로컬 디버그 로그는 빌드 버전, 시드, 모드, 페이즈, 패턴과 이벤트 ID, 피해 원인, 직전 입력, 상태, 회피 나이, 무적 여부, 무기·기운·스택을 담는다. 키 입력은 게임 플레이 입력만 기록한다. 외부 전송은 하지 않는다.

난도 관측은 페이즈 도달률, 패턴별 피격률, 반복 경험에 따른 피격률 변화, 회피 입력 직후 피격 원인, 사망 원인 이해도를 중심으로 한다. 출시 난도를 사망률 하나로 정하지 않는다.

## 개발 모델에 전달할 프롬프트

아래는 첫 개발 세션에 그대로 전달할 수 있는 요청이다. 전체 설계를 읽고 M1과 M2의 전투 핵심을 실제로 검증하도록 범위를 정했다.

```text
이 프로젝트의 README.md, docs/01_GAME_DESIGN.md,
docs/02_BOSS_DESIGN.md, docs/03_IMPLEMENTATION_HANDOFF.md를 먼저 읽어라.

THE ONE은 단 하나의 경기장과 5페이즈 보스를 가진 고난도 2D 액션 게임이다.
이번 작업에서는 개발 인계서의 M1과 M2를 실제 실행 가능한 형태로 완성해라.
Godot 4 계열 안정판과 GDScript를 기본으로 하고 사용한 버전을 기록해라.
프로젝트에 이미 구현이 있다면 이를 먼저 확인하고 이어서 작업해라.

이동, 공격, 회피만 사용하는 조작을 유지해라.
공격의 기본/비기/속성/공명 규칙, 새 누름과 버퍼 무효화,
60Hz 타이밍, 공격별 회피 취소, 피해 중복 방지를 우선 구현해라.
회색 도형으로 경기장, 검, 보스 P1의 세 패턴, 검 비기, 화염 기운,
체력과 사망, 빠른 재도전, 다음 공격 HUD를 완성해라.
P1 전용 프로토타입의 구간 완료를 전체 게임 클리어로 표시하지 마라.

보스 예고와 실제 판정은 같은 기하 데이터를 사용해라.
무적이나 높은 공격력으로 플레이 검증을 대체하지 마라.
필요한 디버그 표시와 관련 자동 검증을 만들고 정상 설정으로 직접 플레이해라.
테스트한 내용과 아직 검증하지 못한 내용을 구분해서 보고해라.

전체 개발 구조는 이후 M3~M5로 확장할 수 있게 하되,
이번 단계에 상점, 일반 적, 서버, 다른 맵, 추가 스킬키를 넣지 마라.
도트 아트 제작은 전투의 입력과 판정이 검증된 뒤에 진행해라.
설계 충돌을 발견하면 먼저 문서의 우선순위에 따라 해석하고,
핵심 게임 방향을 바꾸지 않는 범위에서 해결한 뒤 결정과 이유를 남겨라.

완료 시 실행 방법, 구현된 범위, 검증 결과, 알려진 문제,
다음 단계 M3에서 이어갈 항목을 정리해라.
```
